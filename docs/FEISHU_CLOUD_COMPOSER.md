# 飞书云端组合发送页

这个方案用于在同一轮中提交文字、多张图片和多个文件。页面、表单数据和原始附件都由飞书托管；ClawBridge 只从本机向飞书 OpenAPI 发起出站请求，因此不需要公网 HTTPS、Cloudflare Tunnel 或本机入站端口。

## 推荐模式：飞书原生表单

`singleActive` 直接使用多维表格自带的表单，不需要申请飞书低代码平台。操作流程是：

1. 在当前对话话题点击“组合发送”。按钮会在后台登记当前接收目标，并直接打开飞书表单。
2. 输入文字，选择多张图片和多个文件，一次提交。
3. Bridge 将整条记录合并成一个 Codex turn，并在原话题的一张轮次卡中显示输入和流式回答。

原生表单不能自动携带话题参数，因此这个模式只保留最近一次绑定。如果先在话题 A 点击，又在话题 B 点击，下一次提交会进入话题 B。建议点击后立即填写并提交，不要同时打开多个话题的表单。

## 1. 建立专用多维表格与表单

可以让配置脚本在已有多维表格应用中创建专用数据表、原生表单和所需字段：

```powershell
node scripts/configure-native-composer-form.mjs --app-token <appToken> --dedicated
```

脚本会创建或复用以下字段，并只在表单中展示 `消息内容` 和 `附件`：

| 默认字段名       | 类型     | 用途                               |
| ---------------- | -------- | ---------------------------------- |
| `ClawBridge会话` | 单行文本 | 内部路由字段；原生表单模式保持隐藏 |
| `消息内容`       | 多行文本 | 本轮用户文字                       |
| `附件`           | 附件     | 一次选择多张图片和多个文件         |
| `处理状态`       | 单行文本 | Bridge 写回处理进度                |
| `错误信息`       | 多行文本 | Bridge 写回失败原因                |

文字和附件都不设为必填，以便只发文字或只发附件；Bridge 会拒绝两者同时为空的提交。

## 2. 授权应用

在飞书开放平台为 ClawBridge 的企业自建应用增加下列租户权限，并发布新版本：

- `bitable:app`：读取记录并写回处理状态
- `drive:media:download`：下载附件字段中的飞书云端素材

同时把应用加入目标多维表格的协作者或高级权限成员，授予记录读写和附件读取权限。只有开放平台权限而没有表格本身的访问权时，轮询仍会失败。

## 3. 配置 ClawBridge

把脚本返回的 `formUrl`、`appToken` 和专用 `tableId` 写入未纳入 Git 的 `config/local.yaml`：

```yaml
composer:
  enabled: true
  routingMode: singleActive
  formUrl: https://你的租户.feishu.cn/share/base/原生表单ID
  appToken: bascn_xxx
  tableId: tbl_xxx
  pollIntervalMs: 5000
  maxFiles: 20
  tokenTtlMinutes: 30
```

如使用了不同字段名或状态值，再覆盖 `fields`、`statuses`；完整默认值见 `config/default.example.yaml`。

## 4. 验收

重建并重启 Bridge 后，在一个具体对话话题中点击“组合发送”，表单应直接打开。填写文字并同时选择至少两张图片和一个文件。验收结果应为：

1. 多维表格新增一条记录。
2. 数秒内状态变为 `处理中`，随后变为 `已接收`。
3. 原话题只新增一张完整轮次卡，用户文字和折叠附件位于卡片上部，Codex 回答在同一张卡片下部流式更新。
4. 旧的模型/组合发送工具卡被撤回，新的工具卡出现在最新回答下方。
5. 同一绑定只能成功提交一次；再次提交前需要回到目标话题重新点击“组合发送”。

自动测试覆盖记录读取、附件下载、最近话题路由、一次性消费、状态写回和混合输入提交；仍需用真实飞书客户端提交一次，才能完成端到端验收。

## 可选模式：飞书低代码页面

只有确实需要多个话题同时打开各自的表单时，才需要 `sessionParam` 模式。低代码页面必须读取 URL 查询参数 `clawbridge_session`，并在新增记录时把它写入隐藏的 `ClawBridge会话` 字段，同时写入 `消息内容`、`附件` 和值为 `待处理` 的 `处理状态`：

```yaml
composer:
  enabled: true
  routingMode: sessionParam
  formUrl: https://你的飞书低代码页面地址
  appToken: bascn_xxx
  tableId: tbl_xxx
```

Bridge 会为每个打开动作生成不同的一次性参数，因此这种模式能够并发区分多个话题，但需要已经开通的飞书低代码平台。
