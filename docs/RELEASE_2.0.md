# ClawBridge 2.0 发布与升级

ClawBridge 2.x 在 0.1 稳定基线上增加项目群/话题隔离、任务中心、流式输出、按对话模型设置、远程审批与提问，以及图片和受限文档附件。2.2.1 将对话模型入口压缩为无标题单行卡，模型列表不再显示介绍或返回项目，选择后原位收起；2.2.0 把模型入口移到每个对话话题底部，并在单聊控制台增加只读额度卡；2.1.0 的 SQLite schema v11 进一步增加“待首条任务”的飞书话题路由；2.1.1 修复原位更新卡片未同步 outbox 索引而造成的项目群重建入口失效；2.1.2 为新项目群补充明确群主、机器人管理员和创建后存活性检查，不再保存已经解散的群入口。迁移只增加表和字段，不删除项目、对话、任务或 outbox 历史。

## 升级前

1. 在管理器中停止 Bridge，确认状态不再显示运行中。
2. 备份 `data/clawbridge.db`、`data/clawbridge.db-wal` 和 `data/clawbridge.db-shm`（存在时）。
3. 保留 `%LOCALAPPDATA%\ClawBridge` 中的 DPAPI 凭据文件；升级无需重新输入 App ID、App Secret 或 Open ID。
4. 不要手工编辑 SQLite，也不要把凭据复制到 YAML、命令行或 Git。

## 构建与启动

```powershell
Set-Location D:\CodexWorkspace\claw
npm ci
npm run check
npm run build
npm test
.\scripts\restart.ps1
```

若通过图形管理器操作，点击“构建并重启”即可使用已经保存的加密凭据。首次启动会自动创建附件临时目录并执行数据库迁移。

## 飞书开放平台检查

- 长连接事件已订阅 `im.message.receive_v1` 和 `card.action.trigger`。
- 机器人具备读取用户发给机器人的单聊消息、群话题消息以及下载消息资源所需权限。
- 机器人具备 `im:chat.members:read`、`im:chat.members:write_only` 和 `im:chat:operate_as_owner`，用于检查项目群成员并把主动退出的唯一授权用户重新邀请回原群。
- 修改权限、事件或卡片回调后已创建并发布新的应用版本。
- 项目群功能使用机器人创建的私有普通消息群，群主聊天流放项目控制卡，每个 Codex 对话使用独立话题；不要手工把无关成员加入该群。

## 现场验收顺序

1. 单聊发送“菜单”，检查项目选择、项目群入口和“剩余额度”卡片。
2. 选择一个无敏感数据的测试项目，新建对话并创建项目群。
3. 在对应话题发送普通文本，确认入队和最终回复都留在同一话题。
4. 发送一个只读任务，确认 CardKit 卡片持续更新且最终文本仍可靠发送。
5. 继续已有对话，确认话题底部出现“切换模型”；选择模型和推理强度，再发任务并在任务中心核对快照。任务完成后确认最新工具栏仍位于话题底部；单独发送“模型”也应重新打开设置。
6. 使用只读命令触发一次审批，分别验证“允许一次”和“拒绝”；不要用删除、安装或发布任务做首次测试。
7. 触发一个非秘密选择题和一个自由文本问题，确认回答回到原任务。
8. 分别发送小图片和小型 Markdown 文档，确认 Codex 可以读取；再发送超限文件，确认安全拒绝。
9. 点击“交还桌面”，完整退出并重开 Codex Desktop，确认该对话不再被 Bridge 占用。
10. 主动退出测试项目群，再从机器人单聊点击“项目群”，确认重新回到原群且原话题仍可用；测试群可以单独解散后再次点击，确认新群被创建且 Codex 对话历史仍在。

## 回滚

代码可回到分支基线提交 `581af44`，但旧版本不能理解 schema v10 的新增能力。需要运行旧程序时，先停止 Bridge，再恢复升级前备份的三份 SQLite 文件；不要让旧程序直接复用已经迁移并产生 2.0 数据的数据库。
